## 説明
二部グラフの各入力辺が最大マッチングに必須か、選択可能か、使用不能かを分類する。
左右の頂点数が異なる場合や、完全マッチングが存在しない場合も扱う。
多重辺は入力位置ごとに別の辺として扱う。

## できること
左右の頂点数を $L,R$、入力辺数を $M$ とする。

- `pair<int, vector<int>> bipartite_maximum_matching_edges(int l, int r, const vector<pair<int, int>>& edges)`
  最大マッチングの本数と、入力順の辺分類を返す。
  時間 $O((L+R+M)\sqrt{L+R})$、返却値を含む追加領域 $O(L+R+M)$。

各辺の分類は次の値を取る。

- `0` : 使用不能。どの最大マッチングにも含まれない。
- `1` : 選択可能。一部の最大マッチングに含まれる。
- `2` : 必須。すべての最大マッチングに含まれる。

## 使い方
`edges[i] = {u, v}` は左側の頂点 `u` と右側の頂点 `v` を結ぶ。
`l, r` は非負、頂点番号はそれぞれ $[0,L)$、$[0,R)$ とする。
孤立点があっても分類できる。辺がなければ `{0, 空配列}` を返す。

```cpp
vector<pair<int, int>> edges{ {0, 0}, {1, 0}, {2, 1}};
auto [size, types] = bipartite_maximum_matching_edges(3, 2, edges);
bool required = types[2] == 2;
```

完全マッチングの存在は `l == r && size == l` で判定する。
存在する場合、`types` は完全マッチングについての分類にもなる。

## 実装上の補足
Hopcroft-Karp 法で最大マッチングを1つ求める。
採用辺を右から左、非採用辺を左から右に向けると、交互閉路に沿って採用状態を入れ替えられる。
未マッチの左頂点から到達する辺と、未マッチの右頂点へ到達できる辺も、交互路によって入れ替えられる。
これらの辺は選択可能となり、それ以外は採用辺なら必須、非採用辺なら使用不能となる。

実装では採用辺の左右の頂点対を縮約してから強連結成分分解する。
未マッチの頂点は個別に残し、到達判定を縮約 DAG の順・逆トポロジカル順で行う。
完全マッチングでは DAG の構築と到達判定を省く。マッチング後の処理は時間・領域 $O(L+R+M)$。
多重辺から採用するのは入力辺 ID で1本だけとし、残りは非採用辺として扱う。
縮約で自己ループになる非採用辺も別に記録し、採用辺と交換できることを判定に反映する。
内部の Hopcroft-Karp 法と強連結成分分解は再帰 DFS を使う。大入力では十分なスタック容量が必要となる。

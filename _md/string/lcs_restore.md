## 説明
2つの文字列の最長共通部分列（LCS）を、両入力の添字の組として復元する。
連続区間である必要はなく、最適解が複数ある場合は任意の1つを返す。
長さだけが必要な場合は、bit並列の `lcs_bit.cpp` を使う。

## できること

- `vector<pair<int, int>> lcs_restore(const string& a, const string& b)`
  LCSをなす `(a側の添字, b側の添字)` の列を返す。どちらの添字も狭義増加で、対応する文字は等しい。共通文字がない場合や片方が空の場合は空列。

文字列長を $N,M$、LCSの長さを $L$ とする。共通接頭辞と、それに重ならない共通接尾辞を先に確定する。完全一致や片方が他方の接頭辞なら線形時間となる。
残る長さを $N'\ge M'$ とし、64 bitのword演算を定数時間とすると、時間の上界は $O(1+L+N'M'/64+(N'+256M')\log(2+N'))$。文字maskの構築、DP行の展開、小さい部分問題の通常DPも含む。
作業領域は $O(1+M'+256\lceil M'/64\rceil+\log(2+N'))$、返却列は $O(L)$。
文字列のコピーや、再帰の各段でのDPバッファの保持は行わない。

## 使い方

```cpp
auto indices = lcs_restore(a, b);
string common;
for (auto [i, j] : indices) common += a[i];
```

引数の長さによらず、第1成分は元の `a`、第2成分は元の `b` の添字を表す。
辞書順最小や最も早い添字列は保証しない。

## 実装上の補足
共通の先頭文字・末尾文字を含む最適解が存在するため、入口で両端を取り除いても最適長は変わらない。
残る中央部分にHirschberg法を適用し、長い側を半分に分割する。
前半・後半それぞれのLCS長を求め、和が最大になる短い側の分割位置を選ぶ。
両辺が64文字以上の部分問題では、DP行の隣接差をbit列で保持する。各文字の一致位置との論理演算と多倍長減算で行を更新し、最後にbitの累積和を全prefixのLCS長へ戻す。短い部分問題は通常の1行DPを使う。
逆向きの行も同じ方法で計算する。文字は符号なしbyteとして扱い、文字maskは256種類を用意する。長さ $H,W$ の行計算は $O((H+256)\lceil W/64\rceil+W)$、maskは再帰先へ進む前に解放する。
分割位置を決めた後は同じバッファを再帰先で再利用する。
